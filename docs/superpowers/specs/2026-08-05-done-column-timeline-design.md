# 已完成列的时间线分组 — 设计

日期:2026-08-05
状态:已批准(待实现)

## 背景

Tasks 界面是双栏看板:左「待办」、右「已完成」。已完成列当前是一条平铺列表,按完成时间(`completedAt`,回退 `createdAt`)倒序。任务多了以后,难以一眼看出"今天完成了什么、某天完成了什么"。

## 目标

把已完成列改成**按完成日期分组的时间线**:每个日期一个小标题,组内任务按完成时间倒序,组按日期倒序(今日在最上)。

```
已完成 (5)
 今日
   [x] 重构 config 读取
   [x] 上线 power model
 昨日
   [x] 修复 stream
 0803
   [x] newapi 问题
 2025/1230
   [x] 旧任务
```

## 日期标签规则(`dayLabel(date, now)`)

按**本地时区自然日**划分:

- 今天 → `今日`
- 昨天 → `昨日`
- 今年其它日期 → `MMDD`(零填充,如 `0803`)
- 往年 → `YYYY/MMDD`(如 `2025/1230`)

`dayLabel` 是纯函数,输入完成时间与"当前时间",输出标签字符串。单独实现、单独测试(不依赖 UI)。

## 分组依据

- 分组键 = `completedAt` 的本地自然日。
- **遗留已完成任务**(无 `completedAt`)回退用 `createdAt` 的日期——与现有排序回退保持一致,保证不丢、不崩。
- 分组时用于排序/取标签的"完成时刻" = `completedAt ?? createdAt`。

## 分组与排序算法

1. 取 `doneTasks()`(已按完成时刻倒序)。
2. 顺序遍历,用每条任务的本地自然日作为分组键切段,得到 `[{ label, tasks[] }]`。因为输入已倒序,组自然按日期倒序、组内也倒序,无需二次排序。
3. `label` 由 `dayLabel(effectiveDate, now)` 生成。

## 导航(关键交互)

- 日期标题**不可选中**。
- 已完成列的 `row()` 仍然是"第几条已完成任务"(对**扁平后**的任务序列索引,与分组无关)。
- 渲染时按天插入标题行;选中高亮只落在任务行。`j/k` 在任务之间跳,跨越组标题时无缝。
- 待办列、`h/l` 切换列、`space` 完成跳列、`↑/↓` 待办排序、截断显示等现有行为**全部不变**。

## 展示样式

- 组标题:`theme.textMuted` + bold,顶格带一个前导空格(` 今日`)。
- 任务行:缩进 3 空格 + `[x] ` + 截断后的首行文本(沿用现有 `fit()`)。
- 选中任务:`theme.primary` + bold + `►` 前缀(沿用现有逻辑)。

## 范围

- **只改** `src/tui/routes/tasks.tsx` 的已完成列渲染 + 新增纯函数 `dayLabel`(可放同文件或独立小模块)。
- 新增 `dayLabel` 的单元测试。
- **不动** storage / 类型 / CLI —— `completedAt` 字段已就位。
- 本版**不加滚动**,与当前一致(已完成过多时可能超屏,后续再议)。

## 非目标

- 已完成列滚动。
- 待办列的任何日期/时间线处理。
- 折叠/展开分组。
